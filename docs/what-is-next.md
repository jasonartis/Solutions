# What is next? — the one place to look

> A fresh chat told "let's work on what is next" starts HERE. CLAUDE.md points at this file. Keep it a short index:
> the lists themselves stay in their own docs, so there is nothing here to go stale except the pointers.

## How to answer "what's next"

1. Read the three lists below (in this order) and show the founder the TOP of each, not everything.
2. Never start a build, migration or decision unprompted. Offer; the founder picks; one item per chat.
3. Check each item's model tier first (CLAUDE.md "Model choice") and say so before starting.

## The three lists

| List | What it holds | Where |
|---|---|---|
| **Build ranks** (resilience, backups, vendor plans) | Ordered; "do them all" means start the lowest unfinished rank | [docs/28 B.4a](28-vendor-accounts-and-evacuation-plans.md) (ranked list) + B.4b (a brief per rank) |
| **Decide or discuss** (founder design questions) | Not urgent, none blocks work; ask each as a concrete scenario | [docs/04 "Open founder design questions"](04-build-plan.md) (table, rows 1-7) |
| **Follow-ups on a shipped feature** | Small known gaps, deferred items, "do NOT start unprompted" | CLAUDE.md "Next / open" |

Also open but not on those lists: costs ideas (actuals ledger, receivables, badges) are row 7 of the docs/04 table,
detail in [docs/costs/ideas.md](costs/ideas.md). **Questions to take to a lawyer / insurance broker before the first
client:** [docs/31](31-questions-for-a-lawyer.md) (the one list; add new ones there).

## When something new is decided or finished

Tick it in its own list (strike through + date), add a journal entry (docs/history/platform-journal.md), and only
then touch this file if a pointer changed.
